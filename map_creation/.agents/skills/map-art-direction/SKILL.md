# Establish art direction

Read [art direction](../../../docs/art-direction.md). Use the user's available references and intended display size. Confirm the representation: atlas symbols, regional terrain or household-scale illustration.

Compare a few treatments on the same small scene within the agreed generation budget. Keep content and geography constant; change medium, palette or projection deliberately. If an image tool is unavailable, prepare exact briefs and an explicit manual handoff rather than presenting a procedural guide as a painted trial.

Inspect trials at overview and native size. Compare terrain/house/tree compatibility, readable silhouettes, quiet ground, lighting and likely repeatability. Save the selected reference and its dimensions/hash, then complete `style.json` from [the template](../../../templates/style.json). Record why alternatives were rejected and whether selection is user-confirmed or provisional.

A general style reference does not automatically approve its village layout, river geometry or forest species. Keep component references distinct where needed. If the style changes later, identify which accepted regions need adjustment before generating a batch.

Choose direct painting, reusable source assembly or a hybrid according to the work. Build only assets needed to prove the integrated pilot. For each reusable source, use [asset-record.json](../../../templates/asset-record.json); inspect real alpha, camera, native placement size and ground anchors. Do not rotate baked lighting or squash sprites to fake a different camera.

Return a style comparison, selected/provisional contract, exact prompts, retained source files and the next pilot brief. Do not promise that a reference forces precise model compliance.
